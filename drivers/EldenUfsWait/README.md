# UFS completion IRQ and bounded hybrid waiting

The v151 component stage below has now been integrated and tested on hardware in
[v152](../../profiles/ufs-wait-trial/README.md), with actual IRQ wakes and matched
read hashes. The standalone component build still does not produce a boot image.
This is the first transport delta over the
v150 normal early-watchdog path. It retains v149 storage properties. UFS still
uses slot0, one serialized DMA buffer and the existing read/write gates.

## Reused implementation and board binding

- [ShengUfs b6fe07b3](https://github.com/UniXNU/ShengUfs/tree/b6fe07b307eeddc5e258c9d5d4387b968a55e4e9):
  UTR completion IRQ, generation-before-doorbell observation, 200us initial spin
  budget and assert-wait/recheck/block ordering. Its tree equals57f031c, excluding
  the reverted container changes. A generation is a wake hint, not completion.
- [ArmCpu d90e457b](https://github.com/UniXNU/ArmCpu/tree/d90e457b8392623853ec85c860feef546c767621):
  serialized registration with an atomically published IOLock; masking in primary
  IRQ context without locking or allocation. Elden retains its old16-slot table,
  dispatch, timer, affinity and PSCI code; shared-line registration is not added.
- ArmadaOS TB322FC → h0cheung Linux
  `6f97250ead155fc3b980856323e99a4623dae73d`, `sm8750.dtsi`: UFS SPI265, level-high,
  GIC INTID297. No TB321FU/SM8650 register source is used.

`Source.py` derives exact frozen ArmCpu/RootCommands and the current
`EarlyStorageSource` UFS/recovery pair. Kernel headers are included at translation
unit scope. The recovery input remains the v97 `ce63730b` header with WCN stop,
not the old v91 header. Its new UFS stop call is mandatory in this paired build.

## Behavior and boundaries

Discovery still polls. Successful discovery registers the IRQ and checks GIC
group1/enabled/level, priority0xa0 and boot-core route0 before enabling only UTRCS
at the peripheral. Refusal keeps polling; it does not mask an existing owner's
line. The ISR acknowledges only UTRCS and retains fatal bits for the original
transport. Completion remains the unchanged TransferPoll doorbell/OCS check,
including the final ordered deadline recheck and DMA quarantine.

After200us, a schedulable thread may sleep for at most1ms, shortened to the
remaining command budget. It registers the wait before checking generation
again. Interrupts off, preemption disabled, panic and early polling never sleep.
Elden does not adopt WFE without its per-core event-stream prerequisite.
The host mutex remains held because there is still only one DMA buffer; the
ISR never takes that mutex. Maximum existing transfer size is128KiB.

Startup and shutdown use a terminal Closed state. A racing startup rechecks
after attach/enable and repeats withdrawal; it cannot publish Running after
Closed. Stop disables completion interrupts and wakes waiters, retaining DMA
and polling for existing shutdown I/O. No unregister/free, retry, command
cancellation, controller reset, allocation change or new write window is added.
Generation changes during shutdown and spurious interrupts are not counted as
successful IRQ wakes. Shutdown counters measure commands/wait durations,
interrupts/sleeps/wakes/timeouts/other wakes; they are not CPU utilization or
throughput measurements.

## Validation and reproduction

From the repository, with a fresh output directory:

```sh
python3 tools/test_ufs_wait.py --cxx /usr/bin/clang++ --output /path/to/new/host-output
python3 tools/build_ufs_wait_objects.py \
  --clean-build /path/to/source-built-baseline \
  --parent-build /path/to/qualified-early-storage-build \
  --llvm /path/to/llvm/bin --output /path/to/new/native-output
```

`--clean-build` is generated by the existing clean-build entrypoint and declared
original inputs. Historical paths appearing in compiler diagnostics are virtual
capture names. The closed overlay resolves them to source in this clone/rebuilt
baseline; no historical v99 binary directory is required. This command only
compiles components and must not be used as a flashing command.

50 ASan/UBSan cases passed:36 actual completion/submit cases and14 actual SPI
cases, including two16-thread registration races. They cover early/late wake,
spurious/fatal IRQ, timeout with OCS still15, disabled contexts, bounded waits,
stop during registration/IE enable, duplicate/capacity/invalid registration,
and no DMA reuse after quarantine. Hardware MMIO, cache operations, scheduling
and ARM barriers are modeled, not emulated hardware acceptance.

Both native objects preserve old exports plus exactly their new provider,
original initializer layouts/targets, and contain no FP/SIMD instructions.
New imports resolve to the qualified native baseline plus the paired object.
Old Apple imports still require the original prelink stage. ArmCpu has two
existing signedness warnings; UFS has26 warnings matching the v150 diagnostics
and source expressions. No claim is made that all existing warnings are harmless.

## Integration window (completed in v152)

The original acceptance plan was to integrate the pair into a distinct full profile over v150 normal, checking
the actual parent ArmCpu member, other archive/core members, Apple30 execution
regions, entry and AVB. Add a bounded read-only comparison using the same known
4K/128KiB blocks and full data hashes, measuring polling versus IRQ-wait timing
under matched conditions. The v152 profile now implements and records this window.
Require actual IRQ delivery/wake evidence rather than a configured message,
then typed fastboot return and full stock restoration. No reason to repeat the
already completed watchdog-stall experiment for this component alone.

Proceed to the upstream queue/DMA and authenticated-cache deltas after this
foundation. QD8/32 on the current driver is upper-layer concurrency only; do not
claim hardware parallelism. The full peripheral Goal, charging/endurance,
Wi-Fi and Bluetooth pairing/reconnection remain incomplete.
