## Controller boundary

The session admits the unique CRC/geometry-checked ARMADA_BACKUP partition
on LUN4, exposing only relative reads. The actual submission gate refuses
write-direction commands and checks current DMA admission before each
doorbell. HCE/reset, GCC and SMMU writes are not allowed. The underlying
inherited-controller link/power handling retains its bounded restoration
contract. After release, five saved controller registers are read back;
failed restoration quarantines the session and forbids freeing its arena
or handing control to another payload.

The EFI backend first obtains the current ABL FDT, checks the SM8750 root
compatible, EL1/MMU state, identity VA/PA translations and GCC clock status.
The DMA arena is 8KiB below 4GiB. Fresh SMMUv2 admission requires exact SID60
matching and the accepted bypass/disabled-stage1 plus bypass-stage2 state.
No translation tables are written. Cache maintenance and timer callbacks
are real ARM64 instructions, not successful stubs.

Mapping and clock checks do not make MMIO fault-proof; there is no new
UEFI exception-recovery handler. NOP, capacity, GPT/data reads, controller
release and actual Linux/XNU handoff must still be qualified on the tablet.

## Two commit slots

This revision uses a raw two-slot container inside ARMADA_BACKUP, each
holding a complete FAT image. It is not a single ESP mounted in place, and
requires no GPT change. Slot span is floor(partition_bytes/2) rounded down
to 1MiB. Both spans must be at least 64MiB. A FAT payload starts 1MiB into
each span and is bounded to 256MiB and the span capacity.

The 4096-byte little-endian commit record begins at each slot base:

| Offset | Field |
|---:|---|
| 0 | 8-byte ELDSTG01 magic |
| 8, 12 | u32 version=1, header bytes=4096 |
| 16, 24 | u64 nonzero generation, exact FAT bytes |
| 32 | 32-byte SHA256 of the complete FAT image |
| 64 | u64 computed slot span |
| 72, 76 | u32 slot number, flags=0 |
| 80..4091 | all zero |
| 4092 | CRC32 of bytes 0..4091 |

CRC and SHA protect against incomplete/corrupt updates, not malicious
replacement. This external developer payload intentionally has no AVB
floor of its own; the fixed boot container keeps stock AVB values.

Updates explicitly retain one verified generation. The inactive header is
invalidated and synced, the whole new payload is written and synced, its
read-back SHA checked, then the final commit header is written, synced and
read back. The retained header is rechecked before commit. Do not edit this
container concurrently. Initial installation needs a current partition
backup and device admission, which the offline file tool does not perform.

`edl_work/stage2_store.py` in the working project implements the format and
transaction for local regular files only. It defaults to planning; local
mutation needs `--commit-local-file`. It rejects raw block devices. It does not claim physical power-loss atomicity of an untested UFS
controller. The separate owner-operated `stage2_adb.py` transport now exists;
its default mode only checks local input. `--inspect` admits the LUN4 block
node, 4KiB logical sectors, capacity and absence of mounts/holders. `--apply`
requires a specific verified generation to retain. Initialization additionally
requires a full local backup matching the current complete partition hash.
An update pushes the entire payload once, checks staging, writes the inactive
range, syncs, checks the target SHA and finally commits. It never reboots or
changes signed boot/recovery/GPT. No device run has been performed.

After hashing a selected image in RAM, the loader releases UFS completely,
publishes only a read-only RAM BlockIo volume, binds the existing FAT driver
and loads EFI/BOOT/BOOTAA64.EFI on that explicit volume. It republishes the
current ABL FDT for the child. Failure before StartImage cleans up and
returns. After arbitrary external code runs, a return causes a cold restart
to the fixed bootstrap: UniXNU/drivers can retain events and protocols, so
return alone does not prove global cleanup. Only the independent fixture
consumer enables test return mode to verify detach/retry; production does not.
