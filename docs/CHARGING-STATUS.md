## v140：旁路退出与自动窗口交接

原厂 property28=0 除了停止充电，还置位独立手动旁路标志。v139从旁路切到保护模式时，
若电量高于上限，会把当前停充误认为自动窗口已生效而不清标志；在窗口尚未评估时，
旧主机策略也可能发送28=0，把临时阈值停充变成持续手动停充。实际旧策略配合固定原厂
接口模型复现了两种路径。v140只让明确旁路发送28=0，退出已应用旁路则发送28=1清标志；
其他自动窗口交给原厂阈值、窗口优先级和滞回，不再由主机取两个窗口最小值来强制开关。

## 双口协议与控制范围

原厂 USB-online 是两个输入按优先级汇总的报告：输入0离线时输入1也可更新它。
因此不能把它当作“仅长边在线”，也不能凭字段名称改成 USB || WLS。
WLS GET包装层还可能把底层读取错误记录后返回0，成功应答本身不证明真实测量。
[字段证据](evidence/oem-power-report-map.json)由原固件和反汇编SHA绑定。

原厂 USB SET property5 进入共享投票器，不提供独立短口选择；改变 battery_id 也不选口。
原代码只有旧类型SDP→新类型非SDP的边沿才撤销 i_sdp/USB_ICL 票。双口同时在线时
USB侧可继续是SDP并保留500mA票，即使短口已有PD合同。此处是报告/投票证据，
不能独自当作FET电气路径已完全解释。

保持本机USB2许可的500mA预算；reported current_max900不等于已获得SuperSpeed资格。
不重试已失败的 GLINK WRITE/AP FIFO 路线，不用整个votable override绕过聚合保护。
最新QcomDwc3的MiPPS数据角色请求属于另一平台的兼容充电器认证，不是Y700双口仲裁证据。
本机板级来源继续按ArmadaOS四代README→固定SM8750源码链，不能混用TB321FU/SM8650。
